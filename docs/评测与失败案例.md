# 运维 Copilot 评测与失败案例

本文档是本项目指标、实验条件和失败案例的唯一事实来源。README 只引用摘要；`项目验收标准.md` 定义门槛，不复制实验细节。

## 1. 结果使用规则

每次正式评测必须记录：日期、commit SHA、数据集哈希与样本数、知识/工具样本划分、LLM/Embedding/Rerank 模型、关键参数、硬件、运行命令、总耗时和逐条结果。

以下历史数字来自场景迁移期间的记录。JWT、Embedding 默认值和关联召回后来发生过变化，因此在当前提交上复测前只能称为“历史基线”，不能称为最新结果。

## 2. 评测体系

### 2.1 检索

`backend/scripts/eval_retrieval.py` 比较三条链路：纯向量、向量+BM25+RRF、完整链路+Rerank。候选召回宽度必须大于最终 Top-K，否则 Rerank 只能换顺序，无法改变 Hit@K 集合。

主要指标：Hit@1/3/5、MRR、命中片段平均排名和延迟。检索指标只统计知识问题；工具案例只进入端到端路由门禁，不得混入 Hit@K/MRR。

v1.0 发布门槛同时要求全量知识集 Hit@5 ≥ 85%、MRR ≥ 0.80、完整链路 Hit@5 不低于纯向量，以及固定 17 条 hard 子集的完整链路 MRR 相对纯向量提升 ≥ 0.15。全量 MRR 相对提升继续作为诊断项公开报告，但不替代分层门槛。hard case ID、顺序和评测集 SHA-256 必须写入机器报告，不能在看到结果后重新标注或删题。

### 2.2 路由与生成

`backend/scripts/eval_ragas.py` 使用人工标注关键词计算 context precision/recall，并用独立云端裁判计算 faithfulness 和 answer relevancy。

路由拆为两个指标：

- `knowledge_routing_accuracy`：知识问题没有被误触发成工具操作。
- `tool_routing_accuracy`：工具问题触发了正确工具。

两者不能合并。一个模型可能减少误触发，却把答案改成过度保守拒答，路由数字上升而回答质量不变。

### 2.3 阈值

`eval_rerank_threshold.py` 比较不同 `min_rerank_score` 下的命中率、空 context 和噪声。阈值调整后必须再跑路由与生成评测，不能只优化检索层。

## 4. 代表性失败案例

### 4.1 三阶段文本表示不一致

曾出现向量和 BM25 使用“标题链+正文”，Rerank 只看裸正文的实现。正确根因段落因缺少问题关键词被 Rerank 从前列压到后排，Rerank 反而降低 Hit@5。

结论：Embedding、BM25、Rerank 必须共用 `contextual_text`；由回归测试锁定这一隐式契约。

### 4.2 召回宽度等于输出宽度

早期评测召回 5 条再输出 5 条，Rerank 只能重排同一集合，Hit@5 必然不变，造成“Rerank 无效”的错误判断。

结论：召回候选必须显著大于 Top-K，并同时看 MRR/平均排名和 Hit@K。

### 4.3 评测集过于简单

12 条查询时混合检索已接近满分，任何优化都难以体现。加入口语化、易混淆和无直接术语的 hard case 后，才观察到双路召回与 Rerank 的真实差异。

结论：评测集要有主题区分度、难例和失败分支，不能只用 README 示例问题。

### 4.4 本地 7B 路由过度行动

历史完整评测中，部分知识问题被路由到工具分支。单纯在 Prompt 中强调“不要调用工具”曾把一类错误换成过度拒答，且误伤原本正确的工具案例。

结论：知识路由与工具路由分别报告；Prompt 修改必须对完整评测集回归，不能只修目标 case。

### 4.5 生成阶段编造运行事实

曾出现模型在没有工具结果支持时编造 Deployment 状态或 kubectl 命令。检索命中和路由正确不能保证最终回答忠实。

结论：工具结果逐字引用，回答前保留充分性校验，并独立衡量 faithfulness。

### 4.6 Rerank 阈值的局部最优

历史敏感性实验把阈值从 0.15 调至 0.12，减少空 context 并改善 hard case；继续降低到 0.10/0.08 不再增加命中，只引入噪声。

结论：0.12 是特定语料和模型下的历史选择，不是通用常量；更换 Embedding、Rerank 或语料后必须重跑。

### 4.7 Chunk 元数据提示造成回归

为“处理步骤”chunk 增加路由降权提示的实验只修复了少数案例，却让知识路由整体明显下降。这说明局部合理的规则可能改变模型对整批证据的理解。

结论：元数据只作为辅助；保留关联召回等结构性方案，但任何上线结论以完整评测为准。

### 4.8 幂等键全局唯一导致串会话

模型生成的 `request_id` 可能碰撞。若数据库只按 request_id 全局查找，会话 B 可能拿到会话 A 的写操作结果。

结论：幂等键限定为 `(conversation_id, request_id)`；此类安全回归必须由测试覆盖。
